# Database

One Postgres database and one Drizzle migration history, with tables owned by the layers.

## How it's wired

- **Tables** live in `src/app/layers/<name>/server/database/schema/*.ts`, with an `index.ts` re-exporting them.
- **`src/app/server/database/schema.ts`** composes every layer's schema with `export * from '../../layers/<name>/server/database/schema'`. Both drizzle-kit (`drizzle.config.ts`) and the client read this file.
- **`src/app/server/database/index.ts`** creates the shared `db` client (`drizzle(postgres(DATABASE_URL), { schema })`).
- **`src/app/server/database/migrations/`** holds the single migration history, generated by `npm run db:generate`.
- **`src/app/server/database/seed.ts`** is a one-off script that creates the household, both users and the default budget categories from `.env`.

**Schema files must use relative imports.** drizzle-kit and the seed script (run with `tsx`) execute outside Nuxt, so `~~` and `#layers` aliases don't resolve there. A feature layer references core tables with `../../../../core/server/database/schema/users`.

## Relations

- Core declares only `households ↔ users`.
- Each feature layer declares its own relations, including `one(households)` and `one(users)` back-references, in its own `relations.ts`. Core never lists feature tables, so it never imports a feature layer.
- Relations are only needed for `db.query.*` with `with:`. Today that's used by `GET /api/household` (users) and `GET /api/budget/entries` (category, user).

## Tables (current)

| Layer | Table | Notes |
|---|---|---|
| core | `households` | name, currency (default GBP) |
| core | `users` | email (unique), passwordHash, displayName, householdId |
| finance | `income_sources` | per person: gross/net monthly, pension %, effective dates |
| finance | `expense_categories` | bucket enum `need`/`want`/`saving`, isArchived |
| finance | `budget_entries` | month (first-of-month date), amount, nullable userId (joint); one entry per category, person and month |
| finance | `pension_accounts`, `pension_value_history` | per person |
| finance | `mortgages`, `mortgage_balance_history` | nullable holderUserId (joint); rate type enum |

The conventions every table follows are in [data conventions](../conventions/data-conventions.md).

## Changing the schema

Use the [db-migrator](../../../.claude/agents/db-migrator.md) agent, or follow the same steps by hand:

1. Edit or add tables in the owning layer (and its `index.ts`).
2. `npm run db:generate` (needs `DATABASE_URL` set; generating doesn't connect to the database).
3. Review the generated SQL, then run `npm run db:migrate`.
4. Update this page's table list and the domain page.
